# Docs For Beginner

## Workflow

1. Explain what the user can run first, then why it matters.
2. Keep commands copyable and project-local.
3. Use concrete Godot terms: project root, `res://`, scene, node, script, import.
4. Mention what requires the Godot editor versus what works from the MCP server.
5. Avoid long theory; include a short troubleshooting section when setup can fail.

## Tone

Use plain language and name risks directly, especially for global config, network tools, and overwrites.
